# USL v4.11.5: continued native semantic implementation

The public translation command supports19 selected catalog IDs and emits actual
executable .usl. A portable Python setup includes the byte-identical v4.10 USL
subset interpreter as source. It needs no Codex Python/Node or previous release
to translate these supported profiles. See PORTABLE_UBUNTU.md and
TRANSLATION_API.md. Native differential/conformance testing remains separate and
requires the pinned native hosts and historical audit dependencies.

This separate addon continues from the 277 bounded original-ID profiles in
v4.11.4. The fresh joined SUMMARY.json records how many additional profiles
actually pass; ALL329_PROGRESS.md retains every starting gap, and
ALL606_STATUS.csv/JSON retain every original catalog ID. The 607-ID full
qualification requirements, including USL itself, remain in v4.11.3.

Six independent implementation families work on Lisp, templates, native code,
grammar/assembly hosts, server configurations and compute shaders. Each family
uses real source syntax, generated executable .usl, a native host and independent
intent fixtures. Read each exact_profile and README for its bounds. Bounded
evidence does not complete a language, its libraries, intent proof or standard.
Full-standard qualifications and complete entity tracks remain zero.

All329 logical catalog actors are started before the ready family jobs are
released. Actual native jobs use observed memory and descriptor admission,
including an explicitly estimated reclaimable clean-file-cache allowance.
Resource estimates are not peak-memory guarantees. There is no fixed batch
round limit. Compatible work can share a pure compiled artifact; execution and
effects are observed freshly. Native result observations, dispatches, network
requests and physical processes remain separately labelled per family.

The source registry binds the complete family source identities. A bounded
receipt must identify every assigned ID, its scope, positive observed counts
and outstanding work; raw success flags cannot promote a profile. The original
247 and v4.11.4's30 historical profiles are preserved without a new native
requalification claim. The baseline derivation and regressions reject missing
IDs, borrowed profile identities, erased obligations and forged totals.

Use the existing workspace and immutable previous releases. Native providers
are restored from pinned authenticated public packages or hashed upstream
artifacts. This archive omits native binaries, build caches and the retained
CPython/Node installation. The full native workflow remains an addon requiring
the dependencies listed in DEPENDENCIES.json. The portable command installs only
the Python translation dependencies; it does not install every native host or
the rest of USL's entity subsystems.

Read TESTING_GUIDE.md for the tested workflow and PLATFORM_MATRIX.json for the
actual Debian/Ubuntu checks. Read CONTINUE_FROM_HERE.md to continue all remaining
language, normative semantics, library, proof and entity obligations.
