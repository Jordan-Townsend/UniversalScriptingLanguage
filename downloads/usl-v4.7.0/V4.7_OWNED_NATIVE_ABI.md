# Native buffer ownership and C/Python/USL callbacks

The `usl.owned-i64-abi/1` profile allocates actual C memory, copies typed Python
input into it, passes a native descriptor through a genuine `ctypes` callback,
and frees the allocation explicitly. The `.usl` supervisor can receive the
callback and inspect its borrowed native buffer through named capabilities.
This extends the existing JSON ABI with a bounded ownership mechanism. It is
native execution; arbitrary source translation and foreign garbage collection
interoperability remain unqualified.

Supported execution is Linux with 64-bit pointers, GCC, C11/POSIX pthreads,
native-endian signed 64-bit integers, ranks 1–4, and at most 65,536 elements per
buffer. There are at most 128 live buffers, 128 cancellation tokens and 128
simultaneous callback borrows per loaded library. Ranks, element size, C field
offsets, shape/product, byte strides, alignment and reachable buffer bounds are
validated. Inputs with other element types, arbitrary data addresses, negative
strides or unsupported platforms are not admitted by the Python API.

Owned buffers use C `malloc`/`free`. Borrowed views are read-only and valid only
for the callback invocation. Derived transposes and positive slices share that
same lifetime. The C token expires on success, exception and cancellation;
Python also expires the view object before returning from its callback. The
public API exposes no data pointer or escaping `memoryview`. Release or mutation
while a callback holds the buffer is rejected. Double release, unknown handles,
cross-owner handles, stale views, invalid indices and shape/stride bounds are
explicit errors. Use context managers or explicit release; Python garbage
collection is not a promise of prompt native resource cleanup.

Callbacks run with the native registry mutex unlocked. They can inspect the
same buffer, invoke a nested callback, use other owned buffers, or cancel an
operation. Each nested callback receives a distinct native borrow token. Callback
exceptions return through a structured `OwnedABIError` with the original cause
type and invocation/expiration trace. No interrupted callback is replayed.

`affine(scale, bias)` computes `value * scale + bias` using checked integer
arithmetic. A temporary native candidate is committed only after every element
and the cancellation boundary pass. Overflow and cancellation preserve all
original values. Cancellation tokens are real C atomic flags. The affine loop
polls them; callbacks check cancellation before entry and after return. A Python
callback that blocks or loops indefinitely is not preempted by this API. The
accepted cancellation test cancels an active native callback from another
Python thread and verifies that its borrow expires at callback return.

```python
from usl_systems.owned_abi import OwnedBridge

with OwnedBridge(approved=True) as bridge:
    with bridge.create([1, 2, 3, 4, 5, 6], shape=(2, 3)) as buffer:
        assert buffer.layout["strides"] == (24, 8)
        assert buffer.visit(lambda view: view.sum()) == 21
        assert buffer.visit(lambda view: view.slice(1, 1, 2).sum()) == 7
        buffer.affine(2, -1)
        assert buffer.values() == [1, 3, 5, 7, 9, 11]
```

The executable supervisor is `examples/owned_native_buffer.usl`. It defines a
USL callback, receives a callback-scoped numeric borrow handle from C, checks
sum/index/column results, transforms the owned buffer, verifies its values and
releases it. Native allocation and callback capabilities require the explicit
execution approval argument. The ordinary USL interpreter does not gain them.

```bash
source /workspace/.onboarding/activate-usl.sh
cd /workspace/usl-v4.7.0
python -m tools.qualify_owned_abi --i-allow-native --program examples/owned_native_buffer.usl
python -m unittest tests.test_v47_owned_abi -v
python -m tools.qualify_owned_abi --i-allow-native
```

The last command writes `test_results/v4.7.0_owned_abi.json`. Independent
acceptance includes the fixed 2×3 array's sum 21, transposed element 6, column
sum 7, transformed values `[1,3,5,7,9,11]`, overflow rollback, callback failures,
native callback traces, cancellation, nested callbacks, expiration, double
release, unknown/stale ownership handles, invalid shape and the `.usl`
supervisor's separately specified output. The C source also builds and runs as
a standalone selftest with AddressSanitizer and UndefinedBehaviorSanitizer.
The report retains native compile argv, exit codes and diagnostics; sanitizer
failure cannot become a passing qualification.

The compiled-artifact cache includes hashes of C source, Python wrapper, ABI
contract, actual GCC executable, actual `cc1` and linker, compiler version,
target, flags, platform, pointer size, Python version and byte order. A manifest
records the built library's SHA-256 and is checked before loading or reuse.
The real C structure size/field offsets are compared with `ctypes` at load time.
Source or toolchain changes invalidate the cache. This is a tested finite
profile; sanitizer and acceptance success do not prove all possible native
programs or qualify arbitrary calling conventions, external pointers,
asynchronous callbacks, callbacks after library unload, foreign GC lifetimes,
Windows/macOS ABI operation or all 606 language standards.
