# Typed program discovery with one-use protected qualification

`entity_program_discovery.py` expands the entity beyond its fixed scalar
arithmetic hypothesis family. It constructs actual typed candidate programs from
a versioned finite grammar and runs them as `.usl` against declared discovery
examples. The same grammar can discover list reductions, filtered sums/counts,
filtered maps and Boolean list invariants, plus scalar integer expressions and
predicates. Task names and natural-language descriptions do not select hidden
handwritten task solutions. The generated source remains inspectable.

The grammar is `usl.discovery.typed-grammar.v1`. Inputs are `int` or `list[int]`;
outputs are `int`, `list[int]` or `bool`. Integer expressions contain a variable,
declared bounded constants, absolute value, negation and approved integer
addition/subtraction/multiplication/floor division/modulo. Predicates contain
comparisons, explicit modulo residues and bounded conjunction/disjunction.
Typed list productions are `fold_sum`, `fold_count`, `filter_map`, `all` and
`any`. Expression depth, expression/predicate cardinality and production/operator
sets are declared. Deterministic truncation bounds the candidate language; this
is not exhaustive enumeration of arbitrary programs. Provable pure integer
identities and commutative duplicates are removed without reading example labels.

Inputs contain at most 64 integers within ±1,000,000. Outputs contain at most 64
integers within ±10^18, or one exact Boolean/integer of that contract. Boolean
values are not accepted as integers. Generated programs have no native, OS,
network, import, attribute or device capability. They execute through the real
restricted USL interpreter with a 30,000-operation, one-second and 4 KiB output
ceiling per case, within a whole-discovery deadline up to 30 seconds and at most
4,096 actually considered candidates. These are bounded Python integer semantics;
they do not qualify a native fixed-width ABI or arbitrary foreign-language rules.

Qualification has a separate interface. `seal_suite(document, approved=True)`
stores the independently authored holdout and all-active-skill retention suites
and returns only their opaque ID, commitment hash, types and counts. The discovery
request contains training examples, grammar and budgets; it cannot contain
holdout/retention labels or a supplied candidate source. The search stage queries
public suite metadata only. It records and durably selects the first candidate
matching all discovery examples, binds the chosen source hash to the one-use
suite, then opens protected qualification. A failed holdout or retention test
terminates the run. Search does not resume and retune against that failure.
Qualification inputs must be disjoint from discovery inputs. Previously exposed
holdout inputs cannot be resealed for the same named skill.

This is logical separation within a trusted host. Protected suites are stored in
the local SQLite journal, not an encrypted enclave. A privileged caller can read
the database or deliberately violate oracle independence outside the API. The
system records provenance and enforces the protocol; it does not claim that an
oracle source string establishes independent authority. Failed-test counterexamples
may subsequently become known evidence, but a later candidate needs fresh
protected qualification.

Every actual candidate trial persists its typed program/AST/source digest, checked
examples, observed outputs or runtime errors, operation counts and first
counterexample. `history(run_id)` retrieves the complete ordered history. The
run records enumeration cardinality/time, candidate case executions, interpreter
operations, execution and journal time, qualification time and promotion costs.
The run's end-to-end timer extends from request entry through promotion commit;
the final cost-record refresh is explicitly outside that boundary. The standalone
qualifier also times the complete workflow externally. No speedup is inferred
from those single-run times.

Before promotion, independently supplied retention tests cover every active
skill. For replacement, the candidate must preserve that skill's previous
accepted behavior and typed interface. The active set is checked against the
sealed snapshot again inside an SQLite transaction. Only after passing does the
same transaction write the immutable skill version, active pointer, searchable
evidence memory, consumed suite and completed journal. A rejected repair leaves
active skills unchanged. A stopped worker is recovered to `needs_review`; neither
search nor promotion is automatically replayed. New readers do not interrupt a
live owner.

The public APIs are:

```python
discovery = ProgramDiscovery(data_root)
sealed = discovery.seal_suite(protected_document, approved=True)
request = {**discovery_request, "suite_id": sealed["suite_id"]}
evidence = discovery.discover(request, approved=True, cancel=stop_event)
output = discovery.execute_skill(name, input_value, expected_stdout, approved=True)
trials = discovery.history(evidence["run_id"])
```

`DiscoverySession` supervises the same operations through actual `.usl` with
`artifact`, `seal_discovery_suite`, `discover_program(request,suite_id)` and
`run_discovered_skill(name,input,expected_stdout)`. Its example is
`examples/entity_discovery.usl` and the independent acceptance tables are in
`examples/entity_discovery_imports.json`. The example expects a fresh store;
when prior skills exist, supply explicit retention acceptance for all of them.
The typed list execution API is separate from the older scalar-only
`Entity.execute_skill` and `EntityCycle` input routing.

Current verification:

```bash
python -m unittest tests.test_v47_entity_discovery -v
python -m tools.qualify_entity_discovery
```

Ten regression tests passed. They exercise filtered-square-sum discovery,
filter/map and Boolean invariants, scalar parity, actual `.usl` supervision,
restart/retrieval, strict input/grammar bounds, changed sealed labels producing
the same selected candidate, holdout failure without retuning/reuse,
retention/forgetting rejection, cancellation and an actual child-process crash
after selection without promotion or replay.

The standalone qualification passes eight checks and records 3,655 actual
candidate trials across accepted and deliberately rejected runs. It starts with
an independently accepted older scalar skill, discovers positive-square-sum,
positive-square filtering, positive counting and the all-positive invariant,
retains every prior skill, and verifies separately authored new-input outcomes
after restart. A deliberately incompatible counting repair passes its proposed
task examples but fails old-skill retention and is rejected. A wrong protected
holdout rejects a selected sum program without searching for another candidate.
All generated sources, trial histories, counterexamples, cost records,
qualification outcomes and dependency/environment hashes are in
`test_results/v4.7.0_entity_discovery.json`.

Passing these finite tasks does not prove all inputs, arbitrary natural-language
intent, universal program induction, general autonomous science or human
abilities. No LLM response, neural-weight training or live sensory acquisition is
fabricated by this component. It adds a concrete measured self-study mechanism
with explicit candidate language, experimental evidence and reject/promotion
rules; broader grammars and scientific discoveries require their own contracts
and independent tests.
