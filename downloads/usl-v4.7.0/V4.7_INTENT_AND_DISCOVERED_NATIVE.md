# Intent checks and learned USL native execution

`translation_intent.py` connects the actual original source AST, the independently validated typed IR and the actual generated function AST to an explicit postcondition. Its closed proof domain is one pure integer return using +, −, multiplication and unary signs, with bounded int32 inputs and overflow-free intermediates. It also proves IR and generated expression equality to the original expression. A changed emitted expression fails even if its hash is recomputed. Source/code identity checks, source-domain checks, and wrong-intent counterexamples are retained. This is not a proof of arbitrary natural-language intent, arbitrary effects, all inputs or complete standards.

The native-function profile separately proves the admitted C/C++/Go/Rust/Java/C# source expression and emitted AST against the same contract. It also independently rechecks actual imported IR and caller domains, rejecting tampering before code emission.

The discovered-program bridge reads a promoted skill's actual `.usl` AST, checks its stored identity and explicit input/output types, and retains the discovered body while supplying typed parameter/result declarations. The adapter lowers through the existing Python frontend and shared IR. Fresh original-USL execution and fresh generated Python/JavaScript execution must satisfy independently supplied transfer cases. The bridge has no handwritten implementation lookup by task name. Native failures do not retune or promote the skill. Unsupported discovered operators fail admission.

Scalar output uses the established compatibility policy. Integer-list outputs use exact length followed by ordered elements, one integer per line; expected frames come from the independently supplied list labels. This explicit value contract avoids assuming that aggregate printing has identical rules across languages. Hash records distinguish the discovery journal's canonical-JSON string identity from raw UTF-8 source bytes.

Run the actual `.usl` discovery/native supervisor using a new data directory:

```sh
python -m usl_systems discovery-program examples/entity_discovery_native.usl --imports-file examples/entity_discovery_native_imports.json --data /tmp/usl-new-discovery --i-allow-execution
python -m tools.qualify_entity_discovery
python -m tools.qualify_translation_intent
```

Discovery uses a finite typed grammar, declared examples, one-use sealed holdouts and retention tests covering every active skill. It discovers filtered sums/maps/counts and Boolean invariants, records actual candidate trials and counterexamples, and atomically promotes only passing candidates. Protected labels are opened after candidate selection and cannot be reused to retune a failed search. This logical separation assumes a trusted host; it is not an encrypted enclave or general autonomous learning. The qualifier adds actual native transfer for four discovered skills, including empty lists, negative values and preserved earlier skills.
